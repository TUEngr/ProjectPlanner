My plans

Plans are saved automatically in this browser only. Use Export → JSON file to back up a plan or move it to another computer.

    Plan settings

    One date per line, as YYYY-MM-DD, optionally followed by a label.

    Weekends

    Uncheck a day to schedule work on it, e.g. for a team that works Saturdays.

    Views

    The table is always available. Saved with the plan, so share links show the same tabs.

    Critical path

    Near-critical tasks are drawn in orange: they aren't on the critical path yet, but a short slip would put them there. Use 0 to turn this off.

    Share a read-only link

    Anyone with this link can view a snapshot of the plan as it is now and save their own copy. Edits you make later are not included. Share again to send an update.

    The plan is packed into the link itself; nothing is uploaded to a server.

    Could not import the CSV file

    The importer needs a header row naming the columns and one row per task. Only a Task (or Name) column is required; it also reads Outline level (or WBS), Type, Duration, Predecessors, % complete, Assignee, Notes, and Pinned start. Start, finish, float, and critical are recalculated.

    Download the template, fill it in with Excel or Google Sheets, save it as CSV, and use Open → CSV file again.

      Using Project Planner

      • Views: Table, Gantt, and PERT show one view each. Table/Gantt and Table/PERT show the table above the chart. The selected task is highlighted in every view. A plan can leave out the Gantt or PERT tabs: see Settings.
      • Column widths: drag the edge of a table column heading to resize it, or drag the line between the Gantt chart's task names and its bars. Double-click an edge to reset that column. Notes takes up any spare width. Widths are remembered in this browser for all plans, and the table and Gantt exports (PNG image and Print) keep the proportions you set. Resizing is not available in the phone layout.
      • On a phone the toolbars move into a menu: tap ☰ at the top left. It shows the plan's dates and status, the editing tools (acting on the selected task, named at the top of that section), the views, and Plans, Settings, Open, Export, Print, and Help. Tap outside it, press ✕, or swipe it left to close it. In landscape the split views are left out (there isn't room for two panes), and the editing tools leave the menu open so you can repeat Indent or Move up and watch the result.
      • Adding tasks: + Task adds a row after the selected task (or as the first subtask of a selected summary). Insert adds a row above it. Pressing Enter in the last row's name also adds a task. Delete removes the selected task; its subtasks move up one level and links to it are removed.
      • Keyboard: Enter / Shift+Enter commits a cell and moves down / up the column. Esc cancels the edit. ⌘/Ctrl+Z undoes; ⌘/Ctrl+Shift+Z or Ctrl+Y redoes.
      • Durations are in working days: Monday to Friday, plus Saturday and/or Sunday if they are unchecked in Settings, minus holidays. Type 5, 5d, or 2w. A duration of 0 makes a milestone ◆.
      • Predecessors: list row numbers, e.g. 2, 5SS, 7FF. A bare number is finish-to-start (this task starts after row 2 finishes). SS is start-to-start (starts no earlier than row 5 starts). FF is finish-to-finish (finishes no earlier than row 7 finishes). With several predecessors, the latest constraint wins. Summary tasks can't have predecessors or be one; link their subtasks instead.
      • Dates: start and finish are calculated. Typing a Start date pins the task there 📌; click the pin to release it. Typing a Finish date changes the duration.
      • ⚠ warnings mark problems: a pinned date that breaks a link (it starts before an FS predecessor finishes, starts before an SS predecessor starts, or finishes before an FF predecessor finishes), a circular dependency, or a link to a summary task. Hover the ⚠ for details.
      • Summary tasks: select a task and click Indent to make it a subtask of the row above; Outdent reverses it. Summary rows roll up dates and progress from their subtasks. Double-click a summary row (in the table or the Gantt chart), or click its ▾ / ▸, to collapse or expand it. Each group remembers its own state, so expanding a phase restores its subgroups as you left them. Links to hidden tasks are drawn to the collapsed group's bar, and Export → PNG image and Export → Print show only what is expanded.
      • Reordering: drag a row in the Gantt chart, or drag the row number (⠿) in the table, up or down. A summary task moves with its subtasks. The ↑ / ↓ buttons move the selected task past its neighbor. Links follow the tasks, so predecessor row numbers update automatically.
      • Critical path (red) is the chain of tasks with zero float: any slip in them delays the finish. Float is how many working days a task can slip without delaying the project. Links that drive the critical path are drawn in red. Near-critical tasks (orange) have a little float, at most the number of working days set in Settings (2 by default; 0 turns it off): they aren't critical yet, but a short slip would make them so. A pinned date can set the project finish by itself: if the work leading to it finishes early, that work has float and isn't red. Its float shows how much margin there is, and raising the near-critical setting colors it orange.
      • Gantt chart: FS arrows run from the end of one bar to the start of the next; SS arrows join the left ends of the bars and FF arrows the right ends. The dark stripe inside a bar is % done, the dashed green line is today, and shaded columns are non-working days. Click a row to select it; double-click a task to edit it in the table (double-clicking a summary collapses it instead).
      • Settings (or click the plan name): rename the plan, set the project start date, list holidays (one YYYY-MM-DD per line with an optional label), choose whether Saturdays and Sundays are non-working days (both are by default; changing these reschedules every task), and choose whether the plan includes the Gantt and PERT views.
      • Plans: keep several plans in this browser. From Plans you can open one, start a new blank or example plan, or delete one. Rename a plan in Settings.
      • Shared plans (test version): open Plans and sign in with your Trinity address to see plans shared with you. Share the open plan… makes a shared copy that you own; Access… lets you add Trinity people who can edit or only view. People take turns editing: click Start editing to take the plan's lock, and Done editing to hand it back. While someone else edits, you see their changes as they are saved, and you can't change anything. If an editor goes quiet (tab closed, computer asleep) for 2 minutes, someone else can Take over editing; an editor who does nothing for 15 minutes is switched back to viewing automatically. If you ever lose the lock with unsaved changes, they are kept as a separate plan in this browser. In this test version, shared plans are stored in this browser only, so “other people” means other tabs or windows of the same browser.
      • Saving: plans save automatically in this browser only. Use Export → JSON file / Open → JSON file for backups or to move plans between computers. Clearing browser data deletes local plans.
      • Open menu: JSON file opens a plan saved with Export → JSON file (if that plan is already in this browser you can replace it or keep both). CSV file makes a new plan from a task table, such as one built in Excel or Google Sheets or saved with Export → CSV file. The first row must name the columns; only Task (or Name) is required. It also reads Outline level (or a WBS number like 1.2), Type (Milestone, Summary), Duration, Predecessors (row numbers such as 2, 5SS, matched to a Row column if there is one, otherwise to the line order), % complete, Assignee, Notes, and Pinned start. Start and finish are recalculated; the earliest Start in the file becomes the project start. Dates may be YYYY-MM-DD or M/D/YYYY. Holidays and weekend settings are not in a CSV, so check Settings afterwards. If a file can't be read, you are offered a template CSV to fill in.
      • Export menu:
        • Read-only link… copies a link containing a snapshot of the plan. Recipients can view it and click Save a copy to my plans to edit their own copy. Later edits are not included; share again to send an update. The plan is packed into the link itself, so nothing is uploaded, but very large plans make long links.
        • JSON file downloads the complete plan (tasks, links, settings) for backups or another computer; load it with Open → JSON file.
        • CSV file downloads the task table for Excel or Google Sheets: WBS number, row, task, type, duration, start, finish, predecessors, % complete, assignee, notes, float, critical, and pinned start. It includes tasks inside collapsed groups. It can be opened again with Open → CSV file, but only the task table comes back (not holidays or settings).
        • PNG image downloads what you are looking at as an image (2× resolution, light colors) for reports and slides: the task table on the Table tab, the PERT diagram on the PERT tabs, otherwise the Gantt chart at the current zoom (switch to Weeks or Months first for a long project). Collapsed groups stay collapsed in the image; in the table image, long notes are cut short with “…”.
        • Print… prints the same thing as PNG image, in landscape. A chart is scaled to the page width; the task table flows across as many pages as it needs, with the column headings repeated on each page. Choose “Save as PDF” in the print dialog for a PDF.
      • PERT tab: a network diagram of the same tasks. Each box shows the row number, name, start and finish, duration, float, and assignee. Each task sits one column to the right of its last predecessor, so columns read left to right as the order of work. Arrows are dependencies (SS and FF are labeled), and the critical path is red. Collapsed groups appear as one dashed box; double-click it to expand. Double-click a task to edit it in the table. Since tasks have a single duration, this is a dependency network, not a three-point (optimistic / likely / pessimistic) PERT estimate.

      Bugs and feature requests

      Report problems and suggest features on the GitHub issues page (a free GitHub account is needed). Search the existing issues first; if yours is already there, add a comment or a 👍 instead of opening a new one. Otherwise click New issue and include:

      • Bug: what you did, what you expected, and what happened instead, plus your browser and operating system. A screenshot helps, and so does the plan itself: use Export → JSON file and drag the .json file into the issue.
      • Feature request: what you are trying to do and why. The use case matters more than a specific design.

      Issues are public. Don't attach plans that contain private information.
